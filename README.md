# Шлюз курсов валют Банка России

Web API на ASP.NET Core (.NET 8), через который внутренние системы получают официальные курсы валют Банка России в JSON. Источник — [`XML_daily.asp`](https://www.cbr.ru/development/SXML/) на cbr.ru.

Сервис разработан по Spec-Driven Development: сначала требования, затем дизайн, затем код. Все артефакты лежат в [`specs/`](specs/):

| Документ | Содержание |
|---|---|
| [spec.md](specs/spec.md) | Требования (FR/NFR), критерии приёмки, допущения |
| [design.md](specs/design.md) | Архитектура, контракт API, ADR |
| [tasks.md](specs/tasks.md) | План задач и трассируемость «требование → тест» |
| [openapi.yaml](specs/openapi.yaml) | Описание API в OpenAPI 3.0 (генерируется из кода) |

## API

`GET /api/v1/currency-rates?date={yyyy-MM-dd}&code={ISO 4217}`

| Параметр | Обязательный | По умолчанию |
|---|---|---|
| `date` | нет | сегодня по московскому времени; допустимо `1992-07-01` … завтра |
| `code` | нет | все валюты; три латинские буквы, регистр не важен |

| Код | Когда |
|---|---|
| 200 | Курсы найдены |
| 204 | Валюты с таким кодом нет в данных ЦБ на эту дату |
| 400 | Некорректные параметры (ProblemDetails) |
| 502 | ЦБ недоступен или вернул некорректные данные (ProblemDetails) |
| 504 | ЦБ не ответил вовремя (ProblemDetails) |

На выходные и праздники ЦБ курс не устанавливает, поэтому сервис возвращает последний действующий курс, а в `rateDate` указывает дату, на которую он был установлен:

```http
GET /api/v1/currency-rates?date=2026-09-27&code=jpy
```

```json
{
  "requestedDate": "2026-09-27",
  "rateDate": "2026-09-26",
  "rates": [
    { "charCode": "JPY", "numCode": "392", "name": "Иен", "nominal": 100, "value": 53.1351, "unitRate": 0.531351 }
  ]
}
```

Служебный эндпоинт `GET /health` — liveness-проба, от доступности ЦБ не зависит.

```bash
dotnet run --project DigitalLeagueTask --launch-profile http
```

Swagger UI (только в Development): http://localhost:5120/swagger. Примеры запросов — [DigitalLeagueTask.http](DigitalLeagueTask/DigitalLeagueTask.http).

## Тесты

```bash
dotnet test
```

Unit-тесты и интеграционные тесты через `WebApplicationFactory`. Сайт ЦБ в тестах заменён заглушкой с реальными ответами ЦБ, так что в сеть тесты не ходят. Интеграционные тесты названы по номерам критериев приёмки из спецификации (`AC_1_1_…`).

`specs/openapi.yaml` генерируется из кода. Тест `OpenApiDocumentTests` падает, если файл не совпадает с кодом. После изменения API файл обновляется так:

```bash
UPDATE_OPENAPI=1 dotnet test --filter OpenApiDocumentTests
```

## Docker

```bash
docker build -t currency-gateway .
docker run --rm -p 8080:8080 currency-gateway
curl "http://localhost:8080/api/v1/currency-rates?code=USD"
```

Образ multi-stage: собирается на `dotnet/sdk:8.0`, запускается на `dotnet/aspnet:8.0`. Сервис работает от непривилегированного пользователя и слушает порт 8080.

## Jenkins

[`Jenkinsfile`](Jenkinsfile) выполняет этапы: restore → build → test (отчёт JUnit) → `docker build` → smoke-тест контейнера (`/health`) → публикация в registry (необязательно).

- **Агент:** Linux с Docker и плагином Docker Pipeline, метка `docker`. .NET SDK на агенте не нужен: сборка и тесты идут в контейнере `dotnet/sdk:8.0`.
- **Параметры:** `IMAGE_NAME`, `PUSH_IMAGE` (по умолчанию `false`), `REGISTRY`, `REGISTRY_CREDENTIALS_ID`. Значения registry и учётных данных по умолчанию условные. Чтобы публиковать образ, задайте реальный адрес и создайте в Jenkins учётные данные «Username with password» с указанным ID.

## Конфигурация

Настройки задаются в `appsettings.json` или переменными окружения (`Cbr__TotalTimeout=00:00:10`).

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `Cbr:BaseUrl` | `https://www.cbr.ru/` | Адрес ЦБ |
| `Cbr:AttemptTimeout` | `00:00:05` | Таймаут одной попытки |
| `Cbr:TotalTimeout` | `00:00:15` | Общий таймаут с учётом повторов |
| `Cbr:MaxRetryAttempts` | `2` | Число повторов при временных сбоях |
| `Cbr:RetryBaseDelay` | `00:00:00.500` | Базовая задержка между повторами |
| `RatesCache:CurrentDatesTtl` | `00:15:00` | Сколько хранить в кэше курсы на сегодня и завтра |
| `RatesCache:PastDatesTtl` | `1.00:00:00` | Сколько хранить в кэше курсы за прошедшие даты |

## Асинхронное получение данных ЦБ

Сейчас при промахе кэша сервис обращается к ЦБ прямо во время запроса клиента. Поэтому время ответа и сама возможность ответить зависят от доступности cbr.ru. Я бы разделил получение данных и их выдачу:

- **Загрузка в фоне.** Фоновый воркер (`BackgroundService` или Quartz) по расписанию загружает курсы после их публикации ЦБ, с повторами при сбоях, и сохраняет их в общее хранилище (PostgreSQL или Redis). API читает только из хранилища и к ЦБ во время запроса не обращается.
- **Даты, которых ещё нет в хранилище.** Например, глубокая история. Запрос на загрузку ставится в очередь (RabbitMQ или Kafka), а клиент сразу получает `202 Accepted` со ссылкой на статус (паттерн asynchronous request-reply).
- **Уведомления.** Через тот же брокер можно публиковать событие «курсы обновлены», чтобы внутренние системы не опрашивали сервис.

Заодно снимается ограничение текущей версии: при общем хранилище сервис можно запускать в нескольких экземплярах.
