## 1. Цель и границы ответственности

### 1.1. Цель

Предоставить внутренним системам организации единую точку получения официальных курсов иностранных валют к рублю, устанавливаемых Банком России, в формате JSON по HTTP. Внутренние системы не должны знать формат и особенности источника данных ЦБ.

### 1.2. Границы ответственности

Сервис **отвечает за**:
- приём запроса на получение курсов (по дате и/или коду валюты);
- получение данных с официального сайта Банка России (cbr.ru);
- преобразование данных в единый JSON-формат ответа;
- валидацию входных параметров и единообразное сообщение об ошибках;
- снижение нагрузки на источник за счёт повторного использования ранее полученных данных.

Сервис **не отвечает за**:
- хранение истории курсов (не является системой-источником);
- расчёты на основе курсов (конвертация, кросс-курсы);
- контроль доступа потребителей (обеспечивается сетевым периметром, см. A-3).

## 2. Пользовательские сценарии

Актор во всех сценариях — **внутренняя система** (далее «клиент»).

| ID | Сценарий |
|---|---|
| US-1 | Клиент запрашивает курсы всех валют на текущую дату, не передавая параметров. |
| US-2 | Клиент запрашивает курсы всех валют на конкретную дату. |
| US-3 | Клиент запрашивает курс одной валюты (например, USD) на текущую или конкретную дату. |
| US-4 | Клиент запрашивает курс на выходной/праздничный день и получает последний действующий курс с указанием даты, на которую он был установлен. |
| US-5 | Клиент запрашивает валюту, по которой ЦБ не устанавливает курс на эту дату, и получает ответ «нет содержимого». |
| US-6 | Клиент передаёт некорректные параметры и получает понятное машиночитаемое описание ошибки. |
| US-7 | Источник (сайт ЦБ) недоступен; клиент получает ошибку, позволяющую отличить сбой источника от собственной ошибки. |

## 3. Функциональные требования

### FR-1. Получение курсов всех валют на дату
Сервис по GET-запросу с необязательным параметром «дата» возвращает список курсов **всех** валют, установленных ЦБ на эту дату, с кодом ответа **200** и телом в формате JSON.

### FR-2. Дата по умолчанию
Если параметр «дата» не передан, используется **текущая дата по московскому времени** (UTC+3), независимо от часового пояса сервера.

### FR-3. Фильтрация по коду валюты
Если передан параметр «код валюты», ответ содержит только курс указанной валюты. Код — **буквенный код ISO 4217** (3 латинские буквы), сравнение **без учёта регистра** (`usd` ≡ `USD`). Формат ответа тот же, что и в FR-1: список, содержащий один элемент.

### FR-4. Отсутствие запрошенной валюты
Если код валюты корректен по формату, но курс этой валюты отсутствует в данных ЦБ на запрошенную (фактическую) дату, сервис возвращает код **204 No Content** **без тела** ответа.

### FR-5. Дата без установленного курса
Если на запрошенную дату ЦБ не устанавливал курс (выходной, праздник, ещё не опубликованный курс на завтра), сервис возвращает **последний действующий** на эту дату курс. Ответ содержит и **запрошенную дату**, и **фактическую дату** установления курса.

### FR-6. Состав данных ответа
Успешный ответ (200) содержит:
- запрошенную дату;
- фактическую дату установления курса (по данным ЦБ);
- список валют, для каждой:
  - буквенный код (ISO 4217);
  - цифровой код (ISO 4217);
  - наименование (как в источнике, на русском языке);
  - номинал (количество единиц валюты, за которое установлен курс);
  - курс за номинал, руб.;
  - курс за одну единицу валюты, руб.

Числовые значения передаются числами (не строками) без потери точности относительно источника.

### FR-7. Валидация входных параметров
Сервис отклоняет запрос с кодом **400 Bad Request** и описанием ошибки в формате Problem Details (RFC 9457), если:
- дата передана не в формате `yyyy-MM-dd` или не является существующей календарной датой;
- дата позже **завтрашней** даты по московскому времени;
- дата раньше **1992-07-01** (начало публикации данных ЦБ в используемом источнике, см. A-6);
- код валюты не состоит ровно из трёх латинских букв.

Описание ошибки указывает, какой параметр некорректен и почему.

### FR-8. Ошибки источника данных
- Если источник недоступен, вернул ошибку или данные, которые невозможно разобрать, сервис отвечает **502 Bad Gateway**.
- Если источник не ответил за отведённое время, сервис отвечает **504 Gateway Timeout**.

В обоих случаях тело ответа — Problem Details без раскрытия внутренних деталей (стек вызовов, внутренние адреса).

## 4. Нефункциональные требования

### NFR-1. Производительность и бережное отношение к источнику
- Повторный запрос данных на уже запрошенную дату в пределах срока актуальности обслуживается **без обращения к ЦБ**.
- Данные за **прошедшие** даты считаются неизменными и могут храниться длительно.
- Данные на **текущую и будущую** дату хранятся ограниченное время (настраиваемое, по умолчанию 15 минут), так как ЦБ может опубликовать курс позже.
- Время ответа при наличии данных в памяти сервиса — p95 ≤ 50 мс (без учёта сети клиента).

### NFR-2. Надёжность
- Обращение к источнику ограничено таймаутом (настраиваемым).
- Временные сбои источника (сетевые ошибки, 5xx, 408, 429) обрабатываются ограниченным числом повторных попыток.
- Сбой источника не приводит к аварийному завершению сервиса и не влияет на обслуживание запросов, данные для которых уже есть в памяти.

### NFR-3. Безопасность
- Аутентификация и авторизация не требуются (см. A-3).
- Все входные параметры валидируются (FR-7).
- Ответы об ошибках не раскрывают внутреннюю информацию (стек вызовов, конфигурацию).
- Обращения к источнику выполняются по HTTPS.

### NFR-4. Наблюдаемость
- Структурированное логирование: входящие запросы, обращения к источнику (адрес, длительность, результат), попадания в кэш, ошибки.
- Эндпоинт проверки работоспособности (health check) для оркестратора/балансировщика.

### NFR-5. Конфигурируемость
Адрес источника, таймауты, параметры повторных попыток и сроки хранения данных в памяти задаются через конфигурацию (файлы настроек и переменные окружения) без пересборки.

### NFR-6. Платформа и развёртывание
- .NET 8, ASP.NET Core Web API.
- Сервис запускается в одном экземпляре (см. A-4); должен работать в Linux-контейнере.

### NFR-7. Тестируемость
Каждый критерий приёмки покрыт автоматическим тестом. Тесты не обращаются к реальному сайту ЦБ.

## 5. Критерии приёмки

### FR-1
- **AC-1.1.** *Given* ЦБ установил курсы на 2026-10-01 (в ответе источника 54 валюты), *When* клиент запрашивает курсы с датой `2026-10-01` без кода валюты, *Then* ответ 200, JSON, список содержит все валюты из ответа источника (54), запрошенная и фактическая даты = 2026-10-01.

### FR-2
- **AC-2.1.** *Given* текущее время 2026-09-30 23:30 UTC (2026-10-01 02:30 МСК), *When* клиент выполняет запрос без даты, *Then* сервис запрашивает у источника данные на 2026-10-01, запрошенная дата в ответе = 2026-10-01.

### FR-3
- **AC-3.1.** *Given* на дату есть курс USD, *When* клиент запрашивает код `USD`, *Then* ответ 200, список содержит ровно один элемент с кодом `USD`.
- **AC-3.2.** *Given* на дату есть курс USD, *When* клиент запрашивает код `usd`, *Then* результат идентичен AC-3.1.

### FR-4
- **AC-4.1.** *Given* в данных ЦБ на дату нет валюты `XAU` (код корректен по формату), *When* клиент запрашивает код `XAU`, *Then* ответ 204, тело пустое.

### FR-5
- **AC-5.1.** *Given* 2026-09-27 — воскресенье, и на запрос этой даты источник возвращает курсы с фактической датой 2026-09-26 (суббота), *When* клиент запрашивает дату `2026-09-27`, *Then* ответ 200, запрошенная дата = 2026-09-27, фактическая дата = 2026-09-26.

### FR-6
- **AC-6.1.** *Given* ЦБ установил на 2026-10-01 курс JPY: наименование «Иен», номинал 100, курс 53,1038 руб., курс за единицу 0,531038 руб., *When* клиент запрашивает код `JPY` на дату `2026-10-01`, *Then* элемент ответа содержит буквенный код `JPY`, цифровой код `392`, наименование `Иен`, номинал `100`, курс за номинал `53.1038`, курс за единицу `0.531038` — числами.

### FR-7
- **AC-7.1.** *When* дата = `01.10.2026`, *Then* 400, Problem Details с указанием параметра даты.
- **AC-7.2.** *When* дата = `2026-02-30`, *Then* 400.
- **AC-7.3.** *Given* сегодня 2026-10-01 по МСК, *When* дата = `2026-10-03`, *Then* 400. *When* дата = `2026-10-02`, *Then* запрос принимается.
- **AC-7.4.** *When* дата = `1992-06-30`, *Then* 400. *When* дата = `1992-07-01`, *Then* запрос принимается.
- **AC-7.5.** *When* код = `US`, `USDD`, `U5D`, `ДОЛ`, *Then* 400, Problem Details с указанием параметра кода.
- **AC-7.6.** *Given* оба параметра некорректны, *When* клиент выполняет запрос, *Then* 400, описание содержит ошибки по обоим параметрам.

### FR-8
- **AC-8.1.** *Given* источник отвечает 500 на все попытки, *When* клиент выполняет запрос, *Then* ответ 502, Problem Details без стека вызовов.
- **AC-8.2.** *Given* источник возвращает некорректный XML, *When* клиент выполняет запрос, *Then* ответ 502.
- **AC-8.3.** *Given* источник не отвечает дольше таймаута, *When* клиент выполняет запрос, *Then* ответ 504.

### NFR (проверяемые автоматически)
- **AC-N1.1.** *Given* данные за прошедшую дату уже запрошены, *When* клиент повторно запрашивает ту же дату (с любым кодом валюты), *Then* обращения к источнику не происходит.
- **AC-N1.2.** *Given* данные на текущую дату запрошены, *When* истёк срок их актуальности, *Then* следующий запрос обращается к источнику повторно.
- **AC-N2.1.** *Given* источник вернул 503 на первую попытку и 200 на вторую, *When* клиент выполняет запрос, *Then* ответ 200.
- **AC-N4.1.** *When* выполняется запрос к эндпоинту проверки работоспособности, *Then* ответ 200 и не зависит от доступности ЦБ.

## 7. Вне объёма (out of scope)

- Аутентификация, авторизация, rate limiting потребителей.
- Поиск по цифровому коду ISO и по внутреннему коду ЦБ (`R01235`).
- Запросы за диапазон дат (динамика курсов).
- Другие данные ЦБ: учётные цены драгметаллов, ключевая ставка и т.п.
- Конвертация валют и кросс-курсы.
- Персистентное хранение курсов (БД).
- Распределённый кэш и работа в нескольких экземплярах.
- Локализация наименований валют (отдаются как в источнике).

## 8. Допущения

| ID | Допущение |
|---|---|
| A-1 | Источник данных — официальный сайт Банка России (cbr.ru); выбор конкретного сервиса — в design.md. |
| A-2 | «Текущая дата» определяется по московскому времени, т.к. курсы ЦБ устанавливаются по МСК. |
| A-3 | Сервис доступен только во внутренней сети; защита доступа обеспечивается сетевым периметром. |

| A-5 | Ответ 204 не содержит тела (требование HTTP), поэтому «ответ в JSON» относится только к коду 200 и ошибкам. |
| A-6 | Минимальная допустимая дата — 1992-07-01 (с неё ЦБ публикует курсы в используемом источнике). |

| A-8 | Если в данных ЦБ на дату нет ни одной валюты и код не передан, возвращается 200 с пустым списком. |

| A-10 | Jenkins-агент — Linux с установленным Docker. Адрес registry и учётные данные не известны: задаются параметрами пайплайна с условными значениями по умолчанию, публикация выключена по умолчанию. |
